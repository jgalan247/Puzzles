Random binary numbers

Click 🎲 Random to fill A and B with random values within the current bit-width and mode. In unsigned mode the values are 0 … 2w−1; in signed mode they are −2w−1 … 2w−1−1.

What is two’s complement?

With only w bits you can store 2w different bit patterns. Unsigned uses them all for non-negative numbers (0 to 2w−1). Signed two’s complement uses half of the patterns for non-negative numbers and the other half for negatives:

Bits wUnsigned rangeSigned (2’s comp) range
40 … 15−8 … +7
80 … 255−128 … +127
160 … 65 535−32 768 … +32 767

How to encode a negative number

  • Write the positive number in binary.
  • Invert every bit (1→0, 0→1) — this is the one’s complement.
  • Add 1 — and you have the two’s complement.

Example, 4-bit, −5:

  • +5 = 0101
  • invert → 1010
  • +1 → 1011  =  −5

How to read a signed value

If the most-significant bit (MSB) is 0, the number is non-negative — read it normally. If the MSB is 1, the number is negative — invert all bits, add 1, that’s the magnitude, then put a minus sign in front.

Example, 4-bit 1101: MSB is 1, so it’s negative. Invert → 0010, add 1 → 0011 = 3. Therefore 1101 = −3.

Why use it?

  • One representation for zero — unlike sign-and-magnitude, there is no separate +0 and −0.
  • Subtraction becomes addition — the hardware adder doesn’t need a separate subtraction circuit; it computes A − B as A + NOT B + 1 (visible in the carry-in of bit 0 when you pick the SUB operation here).
  • Overflow is detected easily — exactly when the carry into the MSB differs from the carry out of the MSB.

The signed-overflow flag

The overflow indicator lights up when the signed result doesn’t fit in w bits. For example, in 4-bit signed: 7 + 1 = 8, but 8 doesn’t fit in the range −8 … +7, so the bit pattern 1000 is read as −8 instead of +8 — overflow!

Toggle the signed checkbox above to enter and read values in signed two’s complement; the carry/overflow flags work the same way underneath.
